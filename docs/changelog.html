各版の配布物と詳細は GitHub の Releases にあります。 番号の付け方は、頭の数字が大きな節目 (v5 → v6)、 マイナーが奇数なら新機能の先行版 (5.3 / 5.5)、偶数なら安定版 (5.2 / 6.0)、 3 つめが残っていた不具合の修正 (5.2.1) です。先行版は設定で受け取りを ON にした方にだけ届きます。

5.9.26
先行版・統合

切り替えの仕組みを「モード」ひとつに統合しました

  • これまでレイアウトプリセット・シーン・アイコンモード・重ね・2 種類の切替ボタンという 5 つの仕組みが並立し、どれも重なり合い、同時に有効にでき、裏で取り合いを起こしていました。 これを「モード」ひとつにまとめました
  • モードは 壁紙 / ウィジェットの表示 / アイコン を好きな組み合わせで覚え、 オフ / 常に効かせる / 条件で効かせる のどれかで動きます
  • これまでのレイアウトプリセットとシーンのルールは自動でモードに変換されます。設定し直しは不要です
  • タブの名前を「アイコン」から「モード」に変えました

取り合いを黙って起こさないようにしました

  • 同じもの (壁紙など) を覚えるモードは同時にオンになりません。 オンにしたとき何かをオフにした場合は「◯◯をオフにしました」と表示します
  • 自動で動くのは絵 (壁紙とウィジェットの表示) だけです。 アイコンが動くのは、人がボタンを押したときだけにしました。条件の出入りでアイコンが暴れることはありません
  • 切替ボタンは押すとオン、もう一度押すとオフのトグルになりました。2 種類あったボタンはどちらも同じ動きです

消したもの

  • シーンのタブ (案内だけ残しています)、トレイのレイアウト一覧、切替ボタンの「切り替えるもの」選択、 適用ボタンがウィジェットを書き換える経路 — いずれも役目をモードが引き継ぎました
5.9.25
先行版・修正

モードの条件が効かない問題を修正しました

  • 原因は 2 つありました。ひとつは「今すぐ効かせる」と「条件」を同時に設定できたこと。 手動オンが常に勝つため、条件を変えても何も起きませんでした。 設定を「オフ / 常に効かせる / 条件で効かせる」の一択にまとめ、矛盾を作れなくしました。 両方立っていた古い設定は、条件の方を残します
  • もうひとつは、前面アプリの監視が「全画面時に省電力」がオンのときしか動いていなかったこと。 条件付きモードやシーンがあるときも監視を回すようにしました。 アプリ条件があるときは切り替えの体感を優先し、監視間隔を 5 秒から 2 秒に詰めます

「壁紙を変えたのに変わらない」を防ぎます

  • モードの壁紙が重なっている間に壁紙タブを開くと、「いまモード『◯◯』が効いていて、その壁紙が上に重なっています」と表示します。 ここで変えた内容は土台に保存され、モードが外れたときに現れます
5.9.24
先行版・土台の作り直し

モードが「上に重なる」ようになりました (第1段: 壁紙)

  • これまでの切り替えは保存済みの写しで設定を上書きする方式でした。だから写しを取ったあとに 足したものが消え、手で変えたものが巻き戻る事故が繰り返し起きていました (ウィジェットの全消し、シーンでの消失、壁紙の巻き戻り — 原因はすべてこれです)
  • 設定を「土台」とし、モードはその上に重なるフィルタに変えました。 モードは土台を書き換えません。条件から外れれば自動的に土台へ戻ります
  • 手で変えたものは必ず土台に入るので、モードの切り替えで消えることが構造的に起きません

モードに条件を持たせられます

  • 各モードに「自動で効く条件」が付きました。アプリが前面 / 全画面 / バッテリー駆動 / 時間帯
  • 「このモードを今すぐ効かせる」で手動のオンオフもできます
  • 「壁紙も覚える」をオンにすると、そのモードが効いている間だけ、覚えた壁紙が重なります
  • 効いているモードには「効いています」と表示されます

この先の予定

  • 今回は壁紙だけを重ねの方式にしました。ウィジェットとアイコンも同じ方式へ移します
  • すべて移し終えたら、シーンのタブは役目を終えるので畳みます
  • 従来のシーンとモードの適用ボタンは、これまで通り動きます

5.9.22
先行版・重要な修正

再起動するとウィジェットが全部消える問題を修正しました

  • 5.9.18 で「外したモニタのウィジェットを出さない」ようにした際、モニタの見分けに Windows が 割り当てる内部 ID を使っていました。ところがこの ID は再起動のたびに振り直されます。 その結果、保存済みの ID がどのモニタとも一致しなくなり、すべてのウィジェットが「未接続のモニタ」扱いで 消えていました (実測: 保存 3576360390 → 再起動後 2466824423)
  • モニタの見分けを、機種名と解像度 (例「DELL P2418D」) に変えました。これは再起動しても変わりません
  • 古い ID しか持たないウィジェットは、起動時に自動で新しい方式へ移し替えます。 設定し直す必要はありません
  • 本当に外しているモニタのウィジェットは、これまで通り非表示のままで、つなぎ直せば戻ります

あわせて

  • 「自動起動が効かない」という症状も、原因はこれと同じでした。アプリは正常に起動していて、 ウィジェットだけが消えていたため、動いていないように見えていました
  • 設定のモニタ選択に機種名を表示するようにしました (例「モニタ2 DELL P2418D (1440×2560)」)
  • 同じ事故を繰り返さないよう、再起動を模した検証を自動テストに追加しました

5.9.19
先行版・修正

ビジュアライザーが左側ばかり動く問題を修正しました

  • 解析の細かさが足りていませんでした。128 個の区切りで 0〜24000Hz を分けていたので 1 区切り = 187Hz。音楽のエネルギーはほとんど 2000Hz 以下なので、左端の数本に全部入っていました。区切りを 2048 個 (1 つ約 12Hz) に増やしました
  • 並べ方も直しました。音の高さは倍で 1 オクターブなので、等間隔ではなく対数で割り当てます。これまでの式はむしろ高音側を広げる向きで、逆効果でした
  • 結果、左が低音・右が高音になり、音の高さに合わせてバーの位置が動きます。高音は元々弱いので、右へ行くほど少し持ち上げて見えるようにしました
  • 実測で確認: 60Hz の音は左、700Hz は中央、6000Hz は右のバーが立ちます

バーを 512 本まで増やせます

  • 上限を 96 本から 512 本 に引き上げました
  • 本数に応じて隙間を自動で詰めるので、増やしても 1 本が消えたり重なったりしません
5.9.18
先行版・修正

外したモニタのウィジェットがメインモニタに出てくる問題を修正しました

  • 設定のウィジェット一覧では、そのモニタが外れている間は「未接続のモニタ (つないだら戻ります)」と表示されます。別のモニタへ移すこともできます
  • 既存のウィジェットには、起動時にいまのモニタの ID を一度だけ覚えさせます。設定の変更は不要です
5.9.17
先行版・修正

アイコンを手で動かすと、隠していたアイコンが出てきてしまう問題を修正しました

  • デスクトップのアイコンをドラッグすると、Windows (explorer) が DPI の違うモニタをまたぐ再計算のときに、死角へ退避中のアイコンまで画面へ引き戻すことがあります。これは止められません
  • そこで、隠すモードが当たっている間は 5 秒ごとに見張り、「隠すはずなのに見えている」アイコンを見つけたら黙って隠し直すようにしました。見えているアイコンの位置には一切触りません
  • explorer と押し合いになった場合 (同じ顔ぶれが連続で戻ってくる場合) は、1 分ほど間を置いてから再開します
  • 見張りが動くのは隠すモードの適用中だけです。それ以外のときは何もせず、負荷もありません
5.9.16
先行版

音の出力先を切り替えるとビジュアライザーが止まる問題を修正しました

  • 音の取り込みは開始した瞬間の既定デバイスに張り付くため、出力先を変えると古いデバイスを聴き続けて止まっていました。既定の出力を 2 秒ごとに見張り、切り替わったら自動で取り込み直します (Windows 側で切り替えても追従します)

どの出力の音に反応するかを選べます (複数可)

  • ビジュアライザーの設定に「反応する出力」が付きました。出力デバイスの一覧にチェック (複数可) で、選んだ出力が既定のときだけ動きます
  • 何も選ばなければ、これまでどおりどの出力でも動きます
  • 選んでいない出力の間は、音の取り込み自体を手放して待機します (無駄に聴き続けません)
5.9.15
先行版・修正

ビジュアライザーが動かない・見えなくなる問題を修正しました

  • 出力デバイスの都合で解析が止められたときは、自動で起こします
  • 実機で確認: システム音を鳴らすと波の描画が始まります (ログ: 音を検出 peak=85)

フォルダへのドラッグ&ドロップが効かない問題を修正しました

  • ドロップされたファイルの一覧を、そのままの形 (FileList) で内部の橋に渡していたため、渡った先で空になっていました。File の配列に直して渡すようにしました
  • パスが取れなかったときは「取得できませんでした」と表示します (黙って何もしない、をやめました)

先行版

5.9.12
先行版・修正

モードの上書き保存が不安定だった問題を修正しました

  • 保存するたびに、設定の変更通知が連鎖してアイコンのページ全体が最大 3 回作り直されていました。その最中のクリックは捨てた編集データに書き込まれて消えていたため、「保存した直後のチェックが戻る」という不安定さになっていました
  • 「この内容で保存」は1 回の書き込みにまとめ、画面を作り直さないようにしました。保存の直後にクリックしても、もう消えません
  • 編集中 (クリック直後 1.5 秒) は、外からの画面の作り直しを手が止まるまで待たせるようにしました
  • 保存ボタンは処理中は押せなくなり、二度押しで古い内容を書いてしまう事故を防ぎます

「今の並びを覚え直す」に確認を入れました

  • 別のモードが適用中のとき、そのままの並びで上書きすると意図せずモードが壊れるため、「いま適用中は「X」です。上書きしますか?」と確認するようにしました
  • 保存・適用・覚え直すの結果は、ページのどこにいても見えるトーストで出ます
5.9.11
先行版・総点検

コードを一から総点検しました (8 つの視点で機械レビュー + 検証)

  • 「新しいモードが作れない」の正体: 作成ボタンの配線が、6 つの読み取り処理の後ろにあり、どれか 1 つが一度でも失敗するとボタンがハンドラ無しのまま永久に無反応になっていました。配線を独立させ、読み取りは全部失敗しても先へ進むようにし、結果は画面のどこにいても見えるトーストで出します。Enter キーでも作成できます
